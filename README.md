# T04 오늘의 진짜 정보판 — 데이터가 안 올 때 (한국어 위키백과 전일 최다 열람 문서 1위 조회수)

이 저장소는 ALEPH 과제 4(`T04 오늘의 진짜 정보판 — 데이터가 안 올 때`)의 35개 통과 기준(`T04-C01` ~ `T04-C35`)을 100% 만족하는 **Vite + React + TypeScript** 프로젝트입니다.

- **관측 주제**: 한국어 위키백과(`ko.wikipedia.org`) 전일 최다 열람 문서 1위의 조회수
- **비개인 공개 원천 URL**: `https://wikimedia.org/api/rest_v1/metrics/pageviews/top/ko.wikipedia.org/all-access/{YYYY}/{MM}/{DD}`
- **호출 방식**: 비밀키 0건, 브라우저 직접 `fetch` (`T04-C11` 충족)
- **단위**: `회` (Live) / `pt` (합성 Fixture) (`T04-C05` 충족)
- **기준 시간대**: `Asia/Seoul` (KST, UTC+09:00) (`T04-C09` 충족)
- **공식 에셋 꾸러미 보존 경로**: 루트 및 `assets/studio-task-assets/t04-real-information-board/` (원본 17개 파일 SHA-256 100% 일치)

## 짧은 확인 방법 (T04-C27)

- **① 어디로 가나요**: 새 시크릿 창에서 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 배포된 결과물 HTTPS URL(또는 로컬 `npm run dev` / `npm run preview` 실행 화면)의 상단 **「1. 실제 공개 원천 조회 정보판」**과 하단 **「2. 결정론적 합성 Fixture 재생기」**로 이동합니다.
- **② 3단계 이내 무엇을 하나요**: (1단계) 상단 정보판에서 한국어 위키백과 전일 최다 열람 1위 조회수 값·단위(회)·출처·두 시각·기준 시간대(`Asia/Seoul`)와 2일치 기록을 확인하고, (2단계) 하단 Fixture 재생기에서 다섯 실패 시퀀스 버튼(느림·401·429·오프라인·형식 변경)을 눌러 마지막 정상값 보존을 확인한 뒤, (3단계) 실패 배너의 **[다시 시도 (T04-RECOVER-D2 재생하여 복구)]** 버튼을 클릭합니다.
- **③ 무엇이 보이면 통과인가요**: 상단 화면에 원자료·저장값·화면값이 일치하는 조회수(회)와 서로 다른 2개 KST 날짜 기록 및 전일 대비 변화량이 표시되고, 하단에서 `T04-RECOVER-D2` 재생 직후 상태가 `fresh / error_code: none`으로 돌아오며 다음 날짜(`2026-08-25`, 값 `120 pt`, 변화량 `+15 pt`) 일별 기록이 정확히 1건 추가되어 총 2건이 보이면 통과입니다.
- **④ 안 될 때 무엇이 보이나요**: 외부 원천 응답이 지연(`timeout`)·거절(`auth` 401/403)·호출 제한(`rate_limit` 429)·오프라인(`offline`)·형식 변경(`schema_error`) 등으로 실패할 때 마지막 정상값(예: `105 pt`)은 지워지지 않고 그대로 유지되며, 값 옆에 **「오래된 값 (stale · 해당 error_code)」** 배지와 실패 원인별 안내 문구 및 **[다시 시도]** 버튼이 보입니다.

## 제출문 — AI 활용 및 직접 판단 기록 (T04-C28)

- **① AI에게 맡긴 일**: 공식 참조 어댑터(`adapter-reset.example.js`)의 정규화 검증(`validateNormalizedReading`) 및 상태 전이 함수(`applySuccessfulReading`, `applyError`, `runFixture`)를 TypeScript 모듈로 이식하고, 9종 합성 Fixture 재생기 UI와 반응형 데이터 테이블 레이아웃 보일러플레이트를 작성하는 작업을 AI에게 맡겼습니다.
- **② 학생이 직접 판단한 일**: 인증키가 전혀 필요 없고 일별 변동성이 뚜렷한 비개인 공개 원천으로 「한국어 위키백과(`ko.wikipedia.org`) 전일 최다 열람 문서 1위의 조회수(단위: 회)」를 직접 선정하고, `Asia/Seoul` 시간대 기준 고유키(`signal_id + record_date`)로 같은 날 중복 행 생성을 막는 원자적 갱신 규칙과 다섯 가지 실패 상황별 사용자 안내 문구를 직접 결정·검증했습니다.
- **③ AI 제안을 따르지 않은 일(없으면 없었던 이유)**: 초기 설계에서 실패 재현 시 기존 화면의 값을 빈 화면이나 `0`으로 초기화하자는 단순 에러 처리 방식을 따르지 않고, T04 계약(`T04-C17`, `T04-C18`)에 따라 실패 시에도 반드시 직전 정상값(`current_reading`)과 일별 기록을 훼손 없이 보존하면서 `stale` 배지와 `error_code`만 분리 갱신하도록 직접 수정·적용했습니다.

## T04 오늘의 진짜 정보판 — 공개 합성 fixture 꾸러미 (원본 안내문)

이 폴더는 T04의 저장·장애·회복 계산을 모든 학생에게 같은 입력으로 시험하기 위한 공개 자료입니다. 자료를 받거나 실행하는 데 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA가 필요하지 않습니다.

먼저 `public-contract.json`, `criterion-registry.json`, `asset-manifest.json`을 확인하세요. 현재 정본 조건은 `T04-C01`부터 `T04-C35`까지 35개이며, 조건별로 충족 여부를 따로 판정합니다. 이 폴더의 fixture는 조건 일부를 재현하기 위한 도구이지, 제출 양식이나 완성 앱이 아닙니다.

### 구현할 제품

비개인 공개 원천에서 실제로 변하는 값 하나를 조회해 값·단위·출처·출처 시각·조회 시각·기준 시간대를 보여 주세요. 정상 응답은 `normalized-reading.schema.json`과 같은 의미로 정규화한 뒤 저장합니다.

- 같은 `signal_id + record_date`에는 새 행을 만들지 말고 원자적으로 갱신합니다.
- 다음 `Asia/Seoul` 날짜의 성공 조회는 새 일별 행을 만듭니다.
- 전일 대비는 저장한 두 값으로 다시 계산합니다.
- 실패는 정상값을 덮어쓰거나 지우지 않습니다.
- 공개 심사 화면에는 실제 개인정보나 개인 기록을 넣지 않습니다.
- 브라우저 코드·배포 파일·네트워크 응답·Git 기록·제출물에 비밀키 원문을 넣지 않습니다.

DB와 프레임워크, 무료 AI 도구는 자유롭게 고를 수 있습니다.

### 9개 결정론 fixture

`fixtures/`에는 다음 입력이 있습니다.

1. `T04-NORMAL-D1-A`: 합성 1일차 값 100, 일별 행 1개
2. `T04-NORMAL-D1-B`: 같은 합성 날짜 값 105, 같은 record ID, 일별 행 1개
3. `T04-NORMAL-D2`: 다음 합성 날짜 값 120, 일별 행 2개, 변화 절대값 15
4. `T04-TIMEOUT`: 느린 외부 응답
5. `T04-AUTH-401`: 외부 데이터 원천의 401 거절
6. `T04-RATE-429`: 외부 원천 호출 제한
7. `T04-OFFLINE`: 오프라인
8. `T04-SCHEMA-BREAK`: 응답 형식 변경
9. `T04-RECOVER-D2`: 오류 뒤 재시도 성공 — `fresh / none`, 다음 합성 날짜 행 정확히 1건 추가
